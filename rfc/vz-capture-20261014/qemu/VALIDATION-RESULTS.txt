- The final ordinary-TCG drain wall durations were 8.135 / 7.599 / 7.763 s.
- Two earlier ordinary-TCG after0 runs, using the pre-async QEMU binary
  d9f87943f79c70421208ee199ae76f157e611b03131722e9c75aac38be194842,
  passed the exact short-tail oracle but failed follow-on capture with
  ring_capacity rejection and fatal arecord overrun (0.741 and 3.355 ms).
  The same old binary passed with HVF. Logs show ring saturation; they do not
  identify the exact lower-level scheduling cause. The final passing runs
  must not be presented as proof that host-load sensitivity is permanently
  fixed. No kernel change or buffer-size/error-policy workaround was made.
- The old main-loop g_usleep response injector returned PREPARE success
  after 1507 ms instead of the intended timeout. It was replaced by an
  asynchronous response timer with reset/unrealize cancellation.

  observe XRUN first and return -EPIPE directly. The corrected oracle still
  requires bounded completion, final -EPIPE, zero frames, XRUN state and
  exact -EIO from prepare before reprobe; negative checks reject other states.
- Portability failures were also retained: missing QMP server mode, command

  Scripts now use complete result lines, bounded QMP waits, exact device and
