The direct reset delta exposes synthetic hold/counter properties for control and capture descriptors.
Its reset callback cancels and detaches held descriptors, releases stream-queued descriptors while marking streams inactive, deactivates audio outside the queue lock, and detaches queued control descriptors.
This reset cleanup is part of the backend under test; the result does not establish unmodified-QEMU reset behavior.

The shared build helper validates pristine QEMU source hashes and applies the first three fixture patches before accepting this package's patch as its final `--extra-patch`.
The helper builds only `aarch64-softmmu` and does not ship the QEMU binary.

## Runtime input identity

`scripts/build-runtime-manifest.py` writes a path-independent manifest for the `qemu-system-aarch64` executable, matching KASAN `Image`, generated initrd, and sound modules.
The required sound modules are `snd.ko`, `snd-timer.ko`, `snd-pcm.ko`, and `virtio_snd.ko` from one exact `lib/modules/<release>` directory.

At run time, `support/runtime_inputs.py` verifies every manifest digest and requires QEMU 11.1.2.
It rejects duplicate initrd members, compares packaged module bytes, and checks sound-module dependency indexes.
The kernel release is an explicit CLI argument and must be one path component.

The runner invokes the actual `speaker-test` PCM playback process.
It measures SIGKILL-to-driver-timeout using two `/proc/uptime` samples in the same guest shell command, immediately before the signal and immediately after `wait` returns.
The preserved acceptance interval is 0.75–5 seconds.
Host monotonic time is a 20-second timeout hang guard and a diagnostic only.

The delayed control timer uses `QEMU_CLOCK_VIRTUAL` with a 15-second hold.
The runner proves guest uptime has passed that timer deadline by one additional second and confirms reset left `pending=0` and `completed=0`.
A 60-second host guard detects a stuck guest without substituting host time for the virtual-time deadline.

This source package includes no QEMU executable, kernel, module tree, rootfs, initrd, runtime manifest, or test result.
Generate those artifacts from explicit inputs and save fresh run logs outside this directory.
